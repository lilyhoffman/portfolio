01 / BATCH PROCESSING

Financial Markets Data Platform

Python · PySpark · PostgreSQL · dbt · Airflow

View code & README ↗
  1. 01 Yahoo Finance
  2. 02 Bronze / raw CSV
  3. 03 Silver / PySpark + Parquet
  4. 04 Gold / PostgreSQL + dbt

The problem

Daily market data needs consistent validation and reliable updates before it can support analysis.

What I built

I built an incremental pipeline for five tickers, organized into Bronze, Silver, and Gold layers. PySpark validates prices and enriches records with company information; dbt calculates daily returns and five-day moving averages.

Engineering choices

A composite ticker/date key and transactional loads prevent duplicate records on reruns. Airflow coordinates weekday runs, retries, quality tests, and audit logging.

Result & validation

Repeated runs insert zero duplicate rows, with dbt tests checking required fields, uniqueness, price ranges, and analytics outputs.

02 / EVENT STREAMING

Real-Time E-Commerce Pipeline

Kafka · PySpark · PostgreSQL · Docker

View code & README ↗
  1. 01 Python order producer
  2. 02 Kafka / order events
  3. 03 PySpark / validation + windows
  4. 04 PostgreSQL / orders + metrics

The problem

Orders arrive continuously, and a useful pipeline needs to handle duplicates, late events, and interruptions.

What I built

I created a simulated order producer and a Kafka pipeline that validates incoming JSON, calculates order totals, and aggregates completed orders into five-minute revenue and order metrics by category.

Engineering choices

Event-time windows and a ten-minute watermark handle late data. Spark checkpoints retain offsets and state, while idempotent PostgreSQL writes prevent duplicate orders.

Result & validation

In a restart test, the consumer resumed from its checkpoint and processed events published during downtime without creating duplicate order records.

03 / CLOUD DATA ENGINEERING

Cloud Analytics Data Platform

AWS S3 · Glue · Athena · PySpark · Terraform

View code & README ↗
  1. 01 NYC taxi / source Parquet
  2. 02 S3 Bronze / original data
  3. 03 Glue + PySpark / clean + partition
  4. 04 S3 Silver / Glue Catalog → Athena

The problem

Raw trip records include invalid values and timestamps. SQL analysis needs clean data and a storage layout that supports focused queries.

What I built

I ingested January 2025 NYC taxi data into S3 and used AWS Glue with PySpark to standardize the schema, validate trips, derive duration, and write partitioned Parquet. Glue catalogs the output for Athena SQL queries.

Engineering choices

Partitions follow actual pickup timestamps rather than the source filename. Terraform definitions cover the core infrastructure and were validated; the live AWS resources were created manually.

Result & validation

Quality rules removed 151,061 records (4.35%), producing 3,324,165 clean records from 3,475,226 source records.
